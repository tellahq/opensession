# Orchestrate

Own a standing multi-session program. Coordinate contracts and evidence rather than editing every unit yourself.

1. State a countable done predicate, tracks, unit boundaries, verification floor, authorization boundary, and rough budget. If one session can finish the work, use Autonomous run instead.
2. Run one pilot unit through brief, implementation, independent verification, integration, and report. Fix the contract before fan-out.
3. Discover policy-gated Open Session session tools. Create durable child sessions with self-contained `/pstack` briefs. Ask children own investigation and verification. Code children use isolated worktrees and exclusive files or branches.
4. Use one writer for every file, branch, stack topology, and integration frontier. Separate ownership before adding coordination.
5. Keep a compact ledger of unit id, owner session id, state, branch or PR, exact head, verdict, and evidence. Use an organization-controlled scratch or repository-approved decision trail, never live session databases or hand-edited session state.
6. Let child completion reports wake the coordinator. Do not run sleep loops or repeatedly poll. Check a child once only when a decision needs current status.
7. Integrate continuously through the repository's documented workflow. Reverify rewritten heads. Never reset, clean, switch, force-push, merge, deploy, or publish unless active instructions authorize it.
8. Before each human checkpoint, reconcile reports against real branches, PRs, tests, and artifacts. Child summaries are not proof.
9. On restart or handoff, recover by exact child session ids, branches, PRs, and the ledger. Use policy-gated session tools; never scan transcript storage.
10. Stop spawning near the budget boundary and finish verified integration. Finished but unintegrated work does not satisfy the predicate.

Report counts by state, what changed since the last checkpoint, the verified integration frontier, blocked units, open authorization gates, and links.
